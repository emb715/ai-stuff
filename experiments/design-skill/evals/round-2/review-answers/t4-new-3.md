Review of the settings page in `subtle.html`, most severe first. I read the file only and didn't edit it.

1. **No focus indicator (K-04, D-19, D-27).** `*:focus{outline:none}` removes the focus ring from every control, so keyboard users can't see where they are. Fix: delete that rule and add `:focus-visible{outline:2px solid #2f5bd3;outline-offset:2px}`. Also design hover, active and disabled states.
2. **Two equal filled primary buttons: "Save" and "Publish changes" (H-01, H-02, D-14).** Nothing says which one to press, and "Publish" next to "Save" implies a different scope. Fix: keep one filled primary, labelled "Save changes". Make any secondary action a ghost button, or drop it if it isn't needed.
3. **Member status is shown by colored dots only (C-06, D-62, D-86).** Green, red and amber carry meaning with no text, and the dots are unreadable for colorblind users. Fix: add a text label ("Active", "Suspended", "Pending") with the dot, and add a column header or legend.
4. **Remove is a 32px bare "✕" with no confirmation or undo (K-01, D-35, D-37, D-21).** It's below the 44px minimum target, sits next to the status dot, and a mis-click deletes a member. The ✕ glyph also reads as "close". Fix: use a 44px target, or a text "Remove" in a "⋯" menu. Add a confirmation or an undo toast, and give the button an `aria-label` that names the person ("Remove Ana Torres").
5. **Member rows are broken layout (D-5, D-13, L-01).** The name is an `h3` (17.6px, bold) stacked above the dot and button, which fall to a second line, and there's no row structure. Names aren't headings. Fix: make each row a flex line with the name on the left and the status and action pinned right. Use a `ul/li` with a 48px row height, and make the name plain text at 16px/600.
6. **Muted gray text fails contrast (C-03, C-04, D-80).** `#7d838c` on `#f5f1ea` and on `#eef2f7` is roughly 3.4:1, below the 4.5:1 minimum. It's used for the lede and the help text. Fix: use `#565d66` or darker, which gives about 6:1 or better.
7. **The type scale is arbitrary and the hierarchy is flat (T-01, T-03, H-03).** Sizes of 21.3, 19.4, 17.6 and 16px differ by under 2px, so h1, h2, h3 and body barely differ. Fix: use a 1.25 scale such as 16 / 20 / 25 / 31. Make the h1 clearly dominant, and drop the h3s in Members.
8. **Spacing is off-grid and groups aren't separated (S-01, S-02, S-03).** Values like 17, 23, 13, 11, 9 and 15px are scattered across the file. Fields have a 20px internal gap but only 8px between fields, so the gap between a label and its input is larger than the gap between fields. Fix: use a 4/8px scale. Set the label-to-input gap at 6px and the field-to-field gap at 20px or more.
9. **The help text is a 60-word paragraph at full panel width (T-08, D-49, D-11, D-29).** It's one run-on sentence about a risky action, and it sits detached from the URL field it describes. Fix: cap it at 65ch and shorten it, for example "Links redirect for 30 days, then stop working. Tell your team first." Attach it under the URL input.
10. **The Workspace URL input is a bare value with no affordance (D-9, D-22).** `northline` shows no domain, so users can't tell what they're editing. Fix: add a fixed suffix or prefix such as `.yourapp.com`, and confirm separately before applying a destructive change.
11. **Nested boxes and weak radius math (F-05, F-02, S-05).** White `.inner` cards sit inside blue-gray `.panel` cards, both with 12px radius, which is the same value inside and outside. Fix: drop the inner cards in favor of divided rows (1px border). If you keep the nesting, make the inner radius 8px.
12. **Color palette is inconsistent (C-02, C-05, C-01).** The warm beige page (`#f5f1ea`) sits beside cool blue-gray panels (`#eef2f7`), and red, green and amber are used as status colors. Fix: use one tinted neutral ramp, and keep red and green for genuine status only.
13. **Input heights and sizes are off (K-03, K-02).** The `9px 11px` padding gives inputs about 40px height against 40px buttons, which is close but unmatched. Fix: set both to 44px. Add `autocomplete`, and mark `name` and `url` as required where they are.
14. **The Members section has no purpose (K-05, D-65).** There's no "Invite member" action, no role column and no empty state, so the panel is a list you can only delete from. Fix: add a primary "Invite member" button, a role per member, and an empty state with a single action.
15. **Page width is too wide for a form (S-06, T-08, D-49).** `max-width:1100px` stretches inputs across the full width. Fix: cap the form column at about 640px, or add a side nav and a content column.
16. **Weak labelling and minor details (W-02, D-33).** "Save" is vague, and there's no unsaved-change feedback or saved confirmation (D-19). Fix: label it "Save changes", disable it until the form is dirty, and show "Saved" feedback.
