# Strip Attribution Hook

## Context / Problem

Claude Code adds attribution to PR, issue and comment bodies: the `<!-- claude-projects-attribution: ... -->` comment, a `_Requested by ... [project thread](...)_` line, `🤖 Generated with [Claude Code](...)` / `_Generated by [Claude Code](...)_` footers and `claude.ai/code/session_...` links. Instructions to omit them are not reliable, because the harness asks for them.

Hypothesis: a `PreToolUse` hook that rewrites the tool input through `updatedInput` removes them every time, for both `gh` and the GitHub MCP tools, without changing anything else.

## Scope

- Bash: `gh pr create|edit|comment|review`, `gh issue create|edit|comment`. Inline `--body`/`-b` text is cleaned in the command; `--body-file`/`-F` is pointed at a cleaned temp copy (the original file is untouched).
- MCP: any tool whose name matches `mcp__.*github` (covers `mcp__github__*` and plugin-scoped names). Every string `body` field, nested ones included, is cleaned.
- Returns no `permissionDecision`, so normal permission prompts still apply. Fails open: any error leaves the call as it was.

## Procedure / Steps

Pick one per environment:

**Local, every project (plugin):**

```
/plugin marketplace add emb715/ai-stuff
/plugin install strip-attribution@ai-stuff
```

**Local without the plugin, or any machine with a shell:** run `install.sh`. It copies `hook.mjs` to `~/.claude/hooks/` and adds one `PreToolUse` entry to `~/.claude/settings.json` (idempotent).

**Cloud (claude.ai/code environments):** set the environment's setup script to:

```sh
git clone --depth 1 https://github.com/emb715/ai-stuff /tmp/ai-stuff && sh /tmp/ai-stuff/experiments/strip-attribution/install.sh
```

New sessions in that environment start with the hook in user settings.

Files: `hook.mjs` (the hook), `hooks/hooks.json` + `.claude-plugin/plugin.json` (plugin), `install.sh` (settings installer), `test/hook.test.mjs` (`node --test experiments/strip-attribution/test/hook.test.mjs`).

## Results

- 2026-11-25, unit level: 9/9 tests pass. Heredoc and inline `gh` bodies, `--body-file`, comment footers with a dangling `---`, MCP `create_pull_request` and nested review comments are cleaned; non-`gh` commands, clean bodies and non-GitHub MCP servers pass through untouched.
- 2026-11-25, `install.sh`: run twice against a settings file with other hooks; other keys kept, one entry added.
- Not yet run: a live Claude Code session calling `gh` and the GitHub MCP tools with the hook installed, locally and in a cloud environment with the setup script. Promote only after both.

## Failure Modes / Boundaries

- Only `gh` and MCP tools with `github` in the name. `gh api`, `curl` to the REST API and `--body-file -` (stdin) are not handled.
- Patterns are fixed strings. If the attribution wording changes, it passes through until `PATTERNS` in `hook.mjs` is updated.
- Removal is line-text based: a body that legitimately quotes "Generated with Claude Code" loses that text.
- Cloud: works only if the session reads `~/.claude/settings.json` written by the setup script; unverified.
- The `install.sh` clone fallback fetches `main`; it works only after this folder is merged.
