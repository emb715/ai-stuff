# Strip Attribution Hook

## Context / Problem

Claude Code adds attribution to PR, issue and comment bodies and to commit messages: the `<!-- claude-projects-attribution: ... -->` comment, a `_Requested by ... [project thread](...)_` line, `🤖 Generated with [Claude Code](...)` / `_Generated by [Claude Code](...)_` footers `Co-Authored-By: Claude ... <noreply@anthropic.com>` and `Claude-Session:` commit trailers, and `claude.ai/code/session_...` links. Instructions to omit them are not reliable, because the harness asks for them.

A `PreToolUse` hook that rewrites the tool input through `updatedInput` removes them every time, for both `gh` and the GitHub MCP tools, without changing anything else.

## Scope

- Bash: `gh pr create|edit|comment|review`, `gh issue create|edit|comment`, `git commit` (also `git -C <dir> commit`). Inline text is cleaned in the command; `--body-file`/`-F`/`--file` is pointed at a cleaned temp copy (the original file is untouched).
- MCP: any tool whose name matches `mcp__.*github` (covers `mcp__github__*` and plugin-scoped names). Every string `body` and `message` field (commit messages of `push_files`, `create_or_update_file`), nested ones included, is cleaned.
- PostToolUse on MCP `create_pull_request`: the GitHub MCP server appends `_Generated by [Claude Code](https://claude.ai/code)_` to new PRs after `PreToolUse` has run. The hook then gives Claude `additionalContext` asking it to call `update_pull_request` with the cleaned body. Updates don't get the footer.
- Returns no `permissionDecision`, so normal permission prompts still apply. Fails open: any error leaves the call as it was.

## Procedure / Steps

Pick one per environment:

**Local, every project (plugin):**

```
/plugin marketplace add emb715/ai-stuff
/plugin install strip-attribution@ai-stuff
```

**Local without the plugin, or any machine with a shell:** run `install.sh`. It copies `hook.mjs` to `~/.claude/hooks/` and adds one `PreToolUse` and one `PostToolUse` entry to `~/.claude/settings.json` (idempotent).

**Cloud (claude.ai/code environments):** set the environment's setup script to:

```sh
git clone --depth 1 https://github.com/emb715/ai-stuff /tmp/ai-stuff && sh /tmp/ai-stuff/tools/strip-attribution/install.sh
```

New sessions in that environment start with the hook in user settings.

Files: `hook.mjs` (the hook), `hooks/hooks.json` + `.claude-plugin/plugin.json` (plugin), `install.sh` (settings installer), `test/hook.test.mjs` (`node --test tools/strip-attribution/test/hook.test.mjs`).

## Results

- 2026-11-25, unit level: 13/13 tests pass (commit trailers added in v1.1.0). Heredoc and inline `gh` bodies, `--body-file`, comment footers with a dangling `---`, MCP `create_pull_request` and nested review comments are cleaned; non-`gh` commands, clean bodies and non-GitHub MCP servers pass through untouched.
- 2026-11-27, unit level: 17/17 pass. PostToolUse on `create_pull_request` returns `additionalContext` naming the matching `update_pull_request` tool, the PR number and the cleaned body; other tools and failed creates return nothing. `install.sh` run twice keeps other hooks and adds one entry per event.
- 2026-11-27, cloud: a PR created through the GitHub MCP tool had its header stripped by `PreToolUse`, but the stored body ended with `---` and `_Generated by [Claude Code](https://claude.ai/code)_`, added by the server. `update_pull_request` with the clean body stored it without a footer (emb715/ai-stuff#23).
- 2026-11-25, `install.sh`: run twice against a settings file with other hooks; other keys kept, one entry added.
- 2026-11-25, local: plugin installed at user scope on the owner's machine; a PR opened by Claude Code with the attribution lines in its body landed with body `hello` only (emb715/ai-stuff#17).
- 2026-11-25, cloud: personal claude.ai/code environment with the setup script above; a new session created an issue through the GitHub MCP tool with the attribution lines, and the stored body was `hello` only (emb715/neurodiveragents#33, closed).

## Failure Modes / Boundaries

- Only `gh`, `git commit` and MCP tools with `github` in the name. Commits made by `git commit` with no message flag (editor) and `git commit --amend` without `-m` are not rewritten.
- Only Claude co-author trailers with `<noreply@anthropic.com>` are removed; human co-authors stay. `gh api`, `curl` to the REST API and `--body-file -` (stdin) are not handled.
- Patterns are fixed strings. If the attribution wording changes, it passes through until `PATTERNS` in `hook.mjs` is updated.
- Removal is line-text based: a body that legitimately quotes "Generated with Claude Code" loses that text.
- The footer fix depends on Claude acting on the PostToolUse context. Until it does, the footer is visible on the PR for a moment. A PR created with the `gh` CLI doesn't get the footer at all.
- Cloud: the setup script ends with `|| echo`, so a failed clone starts the session without the hook instead of blocking it.
- The `install.sh` clone fallback fetches `main`.
