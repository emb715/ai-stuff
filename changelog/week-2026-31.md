# Wins

- `change-impact-diagram` experiment promoted to validated skill at `skills/change-impact-diagram/`
- All three modes tested: chat (inline diagrams), recap (dry run + real PR upsert via `gh`), plan (issue → plan block → plan-vs-actual comparison)
- Four diagram types validated on real changes: system map, decision graph, state map, endpoint interaction
- Five-class `classDef` scheme (added `removed` for deleted primitives — visual-recap's four-class scheme cannot represent a deletion)
- Edge-style convention: solid `-->` for current/new paths, dotted `-.->` for deleted paths
- Drift-check protocol for `primitives.yaml`: validate-don't-trust (path + mtime + structure checks) — treats the yaml as a verified cache, not static documentation
- Plan-mode risk-range rule: plan-mode classification must state a range tied to decision graph branches, not a single value
- Confidence table split: plan mode with improvised map is riskier than chat mode with one (plan is where you decide *whether* to do something)
- Block format updated with `###` heading + shields badges line above the `<details>` — block is titled and risk-badged without requiring expansion
- DL012 lint rule added: owner frontmatter field must match `@emb715` exactly; prevents OS-username/git-config drift
- `skills/README.md` index created (didn't exist) — links all three skills with status

# What failed

- First design of primitives-map routing (option B: skip repo-primitive-audit's review phase, run only map+breakdown) was wrong — the review phase is load-bearing; skipping it produces an unverified map that may be fiction. Fixed by routing to the full audit (option A)
- Plan-mode block from an issue classified the change as `composes` (low); the actual PR was `adds` (high). The decision graph predicted the fork but the classification didn't follow it. Fixed with the risk-range rule

# What changed in process

- `primitives.yaml` is treated as a verified cache, not static documentation — the drift check gates its use before every classification
- `scripts/doc_lint.py` is the source of truth for the expected `owner` value; AGENTS.md documents the rule, the linter enforces it
- Plan-mode classification is now a range, not a single value — mirrors the decision graph branches
- Shield badges in the change-impact block are decoration; the `<summary>` text carries the full classification and degrades gracefully if shields.io is down

# Decisions

- Kept the upsert script as mjs, not bash — the splice is `indexOf` + `slice` in JS; bash equivalent is quoting hell on block content with shell metacharacters
- `change-impact-checklist.md` is a complement, not a duplicate — checklist is pre-change decision framework (trigger-driven); this skill is diff-driven visualization. Cross-referenced, not merged
- Block is marker-delimited with fixed section order for future ingestion — a viewer app can parse the block via the GitHub API
